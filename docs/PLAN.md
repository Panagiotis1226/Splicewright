# Splicewright — Native macOS Video Editor (Plan)

## Context
The repo (`Splicewright`) is empty apart from a README. Goal: a Premiere Pro–style non-linear editor for Apple Silicon (M4) Macs that imports, edits on a multi-track timeline, and exports. Required media: SDR (Rec.709) and HDR (HLG / PQ, Rec.2020), 4K30 and 4K60, `.mov`/`.mp4`, H.264 and HEVC (H.265).

Decisions made:
- **Stack: native Swift.** SwiftUI + AppKit for the UI, AVFoundation + VideoToolbox for decode/encode, Metal for rendering.
- **v1 scope:** import → edit on the timeline → export, plus **transitions and titles** and **ProRes proxies**. Basic audio (clip volume, track mute/solo, waveforms) is included because audio tracks are core. Full audio mixing and color grading come after v1.

Why native: the M4 media engine decodes and encodes HEVC, H.264 and ProRes in hardware, and macOS shows HDR (EDR) natively. AVFoundation provides both, so the same render path serves real-time preview and export. A web or C++ stack would have to rebuild all of that.

Assumptions (flag if wrong):
- Minimum OS is **macOS 15 Sequoia**. That covers every M4 Mac and avoids depending on newer AVFoundation APIs I haven't verified.
- Distribution is direct (Developer ID + notarization), not the Mac App Store. v1 runs **without the sandbox**, which keeps media file access simple. The sandbox and security-scoped bookmarks can be added later.
- HDR preview depends on the display. A MacBook Pro M4 (XDR panel) shows real HDR. A MacBook Air M4 has limited EDR headroom, so HDR previews will look tone-compressed there, but export is still correct.

## Format support matrix (v1)
| | Import | Export |
|---|---|---|
| Containers | .mov, .mp4, .m4v | .mov, .mp4 |
| H.264 | 8-bit SDR, up to 4K60 | 8-bit **SDR Rec.709 only** (VideoToolbox has no practical hardware H.264 HDR path) |
| HEVC | 8/10-bit, SDR + HDR (HLG, PQ/HDR10), iPhone Dolby Vision (read as its HLG base layer) | Main (SDR) and Main10 (HDR HLG / PQ) with HDR metadata |
| ProRes | 422 / HQ / LT / Proxy / 4444 | ProRes 422 family (also used for proxies) |
| Resolution / fps | Any; iPhone variable frame rate is conformed | 3840×2160 and 4096×2160 (plus 1080p) at 23.976 / 24 / 25 / 29.97 / 30 / 50 / 59.94 / 60 |
| Audio | AAC, LPCM, ALAC | AAC (mp4/mov), LPCM (mov) |

The user's list repeated ".mp4"; I read it as .mov + .mp4 carrying H.264 or HEVC.

## Architecture
The repo becomes an Xcode app generated by **XcodeGen** (`project.yml`). That keeps the project diffable and avoids hand-editing `.pbxproj`. Most code lives in a local Swift package, split into modules:

```
Splicewright/
  project.yml                       # XcodeGen → Splicewright.xcodeproj
  App/                              # @main app, menus, commands, Info.plist, entitlements
  Packages/SplicewrightKit/
    Package.swift
    Sources/
      SWCore/      # Pure Swift, no Apple frameworks: RationalTime, TimeRange, Project,
                   # Sequence, Track, Clip, Transition, Title, edit operations, undo commands
      SWMedia/     # AVURLAsset probing (codec, fps, HDR transfer), thumbnails, waveform peaks,
                   # proxy generation, media cache, RationalTime <-> CMTime bridging
      SWRender/    # Metal: custom AVVideoCompositing compositor, color pipeline, tone mapping,
                   # transition and title shaders, texture cache
      SWPlayback/  # Builds AVMutableComposition + AVVideoComposition + AVAudioMix from a Sequence;
                   # AVPlayer transport; EDR CAMetalLayer monitor view
      SWExport/    # AVAssetReader/AVAssetWriter export, presets, HDR metadata, progress/cancel
      SWUI/        # Panels: Project bin, Source/Program monitors, Timeline, Effect Controls, Effects
    Tests/         # SWCoreTests (run on Linux + macOS), SWMediaTests, SWRenderTests, SWExportTests
  Splicewright.xcodeproj            # generated from project.yml but COMMITTED (see Build & run)
  Makefile                          # make run / test / release / dmg / doctor
  scripts/make-fixtures.sh          # generates small test clips locally (no git-lfs)
  .github/workflows/ci.yml          # macOS runner: build, test, project-sync check
  .github/workflows/release.yml     # on v* tag: build .dmg and attach it to a GitHub Release
```

Key design choices:
1. **SWCore has no AVFoundation dependency.** It uses its own `RationalTime` (value/rate, following OpenTimelineIO). The timeline model and every edit operation can then be unit-tested anywhere, including this Linux container. The trade-off is a small bridge to `CMTime` in SWMedia.
2. **One render path.** A Sequence is compiled into an `AVMutableComposition` plus an `AVVideoComposition` backed by a **custom Metal `AVVideoCompositing`** class (`supportsHDRSourceFrames = true`). AVPlayer uses it for preview and AVAssetReader uses it for export, so what you see is what you export. Overlapping clips (transitions, V2 over V1) go on separate composition tracks. The compositor gets per-frame instructions that list the layers, their opacity, and any transition progress.
3. **Color pipeline.** Source frames arrive as 10-bit 4:2:0 `CVPixelBuffer`s (`420YpCbCr10BiPlanarVideoRange`). Each one is converted in a Metal shader to a **linear-light Rec.2020 working space in `rgba16Float`**, using the source's tagged matrix, transfer function (709 / HLG / PQ) and primaries. Compositing happens in that working space, and the result is encoded to the sequence's output space. Each Sequence has a color setting: *Rec.709 SDR*, *Rec.2100 HLG* or *Rec.2100 PQ*. HDR placed on an SDR timeline is tone-mapped (BT.2390-style curve). SDR placed on an HDR timeline is mapped to 203-nit reference white (BT.2408).
4. **HDR preview.** Monitors are `CAMetalLayer` views with `wantsExtendedDynamicRangeContent = true` and an extended-linear colorspace. They read `NSScreen.maximumExtendedDynamicRangeColorComponentValue` so the image scales to whatever headroom the display has.
5. **Editing model.** The Project holds Bins, MediaItems, and Sequences. Each Sequence holds video and audio Tracks, and each Track holds Clips (with source in/out, timeline start, linked audio/video ID and properties) and Transitions. `Project` is a value type and every edit is a pure `mutating` function on it. Undo keeps the previous `Project` value and registers it with `UndoManager`, which is simpler than a command pattern and, with copy-on-write, cheap. The document is a `.splicewright` package holding `project.json` (Codable) and is a SwiftUI `ReferenceFileDocument`, which supplies autosave. Thumbnail and waveform caches live in `~/Library/Caches`. Proxies will go in the package's `Cache/` folder (M7).
6. **Timeline UI.** The timeline is a custom AppKit `NSView` drawn with Core Animation layers, embedded in SwiftUI. Pure SwiftUI can't handle thousands of clips, drag-trimming and 60 fps scrubbing. Thumbnails and waveforms render asynchronously from the cache.

Implementation notes (M0–M1):
- Modules are added when their milestone begins. M1 ships SWCore, SWMedia and SWUI.
- Xcode 16+ is required because the committed project uses project format 77.
- The Source monitor uses `AVPlayerView`, which handles HDR/EDR presentation itself. The Metal EDR view described in design choice 4 applies to the Program monitor (M3/M4).

Implementation notes (M2–M3):
- **Undo.** Timeline edits are pure `mutating` functions on `EditSequence`, including insert, overwrite, lift, extract, ripple delete, move, trim, ripple trim, roll, slip, slide and razor. Drags edit a preview copy and commit it as a single undoable change.
- **Sync lock.** Ripple edits also apply to sync-locked tracks. On those tracks, clips that span an insert point are split, and extracted ranges are removed as well, so the tracks stay in sync.
- **Program monitor.** It uses `AVPlayerView` with the custom Metal compositor. AVKit presents HDR output on EDR displays, so the dedicated CAMetalLayer monitor is deferred until it's needed (e.g. for scopes).
- **Audio meters.** They currently read cached waveform peaks at the playhead, which is an approximation. True post-mix metering needs an audio tap and is planned for later.
- **Smoke test.** `scripts/smoke-test.sh` launches the real app in CI. It imports generated media, builds a sequence, plays it and checks undo. It saves a window snapshot and a screenshot.

## Premiere-style layout (v1)
A fixed four-quadrant layout built from resizable `NSSplitView` panes. Drag-to-dock workspaces are deferred.
- **Top-left:** Source Monitor, with tabs for Effect Controls and Effects (transitions, titles).
- **Top-right:** Program Monitor (transport, timecode, proxy toggle, playback resolution Full / ½ / ¼).
- **Bottom-left:** Project panel (bins, list and icon views, media metadata columns: codec, fps, resolution, color space).
- **Bottom-right:** Tools strip, the Timeline (V1–Vn, A1–An, track headers with lock / mute / solo / eye / sync-lock), and audio meters.
- **Premiere keyboard map:** V selection, C razor, B ripple, N rolling, Y slip, U slide, A track-select-forward, H hand, Z zoom. Also J/K/L shuttle, I/O marks, `,` insert, `.` overwrite, `;` lift, `'` extract, ⌘K add edit, S snapping, ⌘L link/unlink, ⌘D default transition, and Shift-Delete ripple delete.

## Milestones
Each milestone ends with something you can run.

**M0 — Scaffolding (≈1 wk)**
XcodeGen project (committed), SPM modules, Makefile, README quick start, CI on a GitHub macOS runner (build, test, project-sync check, SwiftLint), fixture script, and an empty window with the four-panel layout. Done when a fresh clone builds and runs with ⌘R on your M4 and nothing else installed.

**M1 — Import and Project panel (≈2 wk)**
- Import through a file dialog or drag-drop.
- `MediaProber` (SWMedia) reads codec, dimensions, nominal and minimum frame rate (to detect VFR), bit depth, color primaries, transfer function and matrix, and audio channels. It uses `AVURLAsset.load(.tracks)` and the format description extensions.
- Thumbnails come from `AVAssetImageGenerator`. Waveform peaks come from `AVAssetReader` PCM output.
- The Source monitor plays clips and sets I/O marks.

**M2 — Timeline model and editing (≈4 wk)**
- In SWCore: sequence presets (4K30 and 4K60, SDR or HDR, frame rate), insert/overwrite, lift/extract, razor, ripple/roll/slip/slide trims, snapping, linked A/V selection, track add/remove/lock, and undo/redo.
- This milestone carries the heaviest unit-test coverage.
- The Timeline NSView gets zoom, scroll, playhead, drag-move, trim handles, and clip thumbnails and waveforms.

**M3 — Playback engine (≈4 wk)**
- `CompositionBuilder` turns a Sequence into an AVComposition, video composition and audio mix. It rebuilds incrementally, with a debounce after each edit.
- The Metal compositor draws multi-layer video with opacity. The Program monitor gets JKL shuttle, frame stepping and dropped-frame stats.
- Target: 4K60 10-bit HEVC with 2 layers plays at full resolution in real time on a base M4.
- Basic audio: clip gain, track mute/solo, and a peak meter.

**M4 — Color management (≈2 wk)**
- Per-sequence color space, source interpretation override, and HLG/PQ → linear → output shaders.
- HDR↔SDR tone mapping, EDR monitor, and a false-color/clipping overlay for debugging.

**M5 — Export (≈3 wk)**
- An Export dialog with presets:
  - H.264 SDR 4K30/60 in mp4
  - HEVC SDR in mp4 or mov
  - HEVC Main10 HLG in mov or mp4
  - HEVC Main10 PQ (HDR10) in mov or mp4
  - ProRes 422 HQ in mov
- `AVAssetWriter` gets `AVVideoColorPropertiesKey`. HDR exports get Main10 profile and HDR metadata insertion (mastering display and content light level).
- Bitrate control, whole-sequence or in/out range, background export with a progress bar and cancel.

**M6 — Transitions and titles (≈3 wk)**
- Cross dissolve, dip to black, dip to white and film dissolve (a gamma-space dissolve), with adjustable duration and alignment (center / start / end on cut). Handles are validated so a transition can't run past the clip's source media.
- Titles: a Title clip type. Core Text renders it into a cached texture (font, size, color, stroke, shadow, position, safe-area guides). On HDR sequences, title white sits at reference white.
- *As built:*
  - **Anchoring.** Transitions live on tracks and refer to their clips by ID, so they follow every edit. Razor re-anchors them, and an edit that separates the clips prunes them.
  - **Rendering.** The builder packs a track's clips onto A/B composition tracks only where a transition needs both at once. Where the source has no handle, it holds the first or last frame instead of refusing the transition, as Premiere does; the timeline marks such transitions with a red corner. Each side renders to a scratch texture and the two are mixed premultiplied, so lower tracks stay hidden behind an opaque dissolve.
  - **Extras.** Wipes and constant-power/gain audio crossfades were added.
  - **Titles.** Titles are per-clip (`Clip.title`) rather than project items.

**M7 — Proxies (≈2 wk)**
- "Create Proxies" on bin items writes ProRes 422 Proxy at 1920×1080 (or half resolution) through AVAssetWriter in a background queue. Proxies keep the source's color tags and are saved in `Cache/Proxies`.
- The Program monitor proxy toggle swaps sources inside `CompositionBuilder`. **Export always uses the full-resolution originals.**
- *As built:*
  - **Location.** Proxies live in one app folder, `~/Library/Application Support/Splicewright/Proxies`, which can be changed in Settings, rather than inside each project. They are found by the source file's path, size and date, so every project using a file shares its proxy, and a changed source file needs a new one.
  - **Format.** Proxies are video only; audio plays from the original. They are made at 1080p, 720p or half size in HEVC (the default: about 6 Mbps at 1080p30, Main10 for HDR), H.264, ProRes 422 Proxy or LT, with a key frame every half second and no B-frames for scrubbing. Both monitors have a toggle.
  - **Caches.** Settings ▸ Media Cache measures and deletes thumbnails, waveforms and proxies.
  - **Workspaces.** Window ▸ Workspaces saves and switches layouts, and layouts are kept automatically.

**M8 — Hardening (≈2 wk)**
Autosave and crash recovery, relinking missing media, preferences, performance passes with Instruments (Metal System Trace, Allocations), and signing plus notarization.
- *As built:*
  - **Auto-save.** Timestamped copies of changed projects every few minutes in `Application Support/Splicewright/Auto-Save`, written atomically and pruned to a set number; a marker file detects a session that didn't quit normally, and the next launch offers the latest versions. NSDocument's own autosave-in-place still restores open documents.
  - **Missing and changed media.** Offline clips render a red Media Offline frame (playback and export). Link Media asks for one file and matches the rest by name in that folder tree, preferring the same size. Files whose size or date changed are re-probed on open and when the app becomes active.
  - **Copy/paste.** Clips copy with relative tracks and times (and their media, so they paste across projects); Paste Attributes copies motion and volume keyframes.
  - **Logs** go to `~/Library/Logs/Splicewright`, rolled over at 2 MB.
  - **Notarization dropped** for now: it needs a paid Apple Developer account. Releases stay unsigned (ad hoc), opened once via Privacy & Security ▸ Open Anyway.
  - **Keyframes were pulled forward** from the post-v1 list: Position, Scale (uniform or not), Rotation, Anchor Point, Opacity and Volume, with Linear, Ease In/Out and Hold, stored in source time so they stay with the picture when clips are trimmed. The Program monitor has a transform box.

**M9 — Captions (added after v1 planning)**
- *As built:*
  - **Recognition.** On-device only, with no bundled model and no third-party code. macOS 26: `SpeechAnalyzer` + `SpeechTranscriber` with per-word audio time ranges, and the language model installs on demand through `AssetInventory`. macOS 15: `SFSpeechRecognizer` with `requiresOnDeviceRecognition`, in 50 s pieces with a 1 s overlap split at its middle. The sequence's audio is mixed down through the playback `CompositionBuilder` (16 kHz mono), so gain, fades, keyframes and mute/solo all apply and the timing matches the timeline.
  - **Model.** Caption tracks on `EditSequence` (schema 5) hold captions with text and the word timings they came from, plus a style (a `TitleSpec` and line limits). Edits keep captions sorted and non-overlapping. The segmenter breaks at sentence ends, pauses over 0.7 s and line limits, between 0.8 and 7 s per caption, with two balanced lines.
  - **Rendering.** Enabled caption tracks become title layers on top of all video, so the Program monitor and burn-in share the title renderer. Export turns on only the track chosen for burn-in and writes the sidecar SRT/VTT clipped to the exported range.
  - **CI** moved to the macOS 26 runner (Xcode 26) to compile SpeechAnalyzer. With Xcode 16 the app still builds and uses the older engine. Real recognition tests run only with `SPLICEWRIGHT_TEST_SPEECH=1`, because CI machines can't grant speech permission.

**M10 — Speed and Time Remapping**
- *As built:*
  - **One timing model.** `ClipTiming` maps sequence frames to source time for every clip. At 100% it is frame-exact (the old arithmetic, so existing edits behave the same). At a constant speed it scales, running backwards when reversed. With Time Remapping it integrates keyframed speed: per-frame trapezoids, which are exact for linear keyframes, and 0% holds a frame. Speed keyframes are timed from the clip's start because source time depends on them; the other properties stay in source time, so motion stays with the picture.
  - **Edits.** Trim, ripple, roll, slide, slip, razor and clear all go through it (`moveStart`, `framesBefore`, `maximumDuration`), so retimed clips trim by the source they actually have. Speed/Duration keeps each clip's source and changes its length, with an optional ripple. Rate Stretch keeps the source and changes speed with length.
  - **Playback and export.** Constant forward speed is one scaled AVFoundation edit, and audio is resampled with the item's time-pitch algorithm (spectral, or varispeed when every retimed clip turns Maintain Pitch off). Reversed and remapped video are built one frame per edit, showing the source frame at each mapped time. AVFoundation can't play audio backwards or along a curve, so that audio is silent; a custom audio renderer would be needed. Premiere also leaves audio out of Time Remapping.

**M11 — Markers**
- *As built:*
  - **Model.** Sequence markers (`EditSequence.markers`, schema 7) have a frame, an optional duration, a name, comments, one of Premiere's eight colors, and a chapter flag. They stay where they are on ripple edits, as Premiere's default does. Clip markers live on the media item in source time, so they show on every clip that uses that part of the file and follow speed changes.
  - **Chapters.** YouTube text uses the markers flagged as chapters (or all of them when none are): the first moves to 0:00, ones closer than 10 s are dropped, and fewer than three gets a warning. Markers also export as CSV.
  - **Chapter marks in exports.** These are written as a disabled 3GPP text (tx3g) track that the video track references as its chapter list, the way iTunes and QuickTime store chapters. A timed-metadata track was tried first, but AVFoundation didn't read it back as chapters in .mp4.

Total: roughly 6 months for one experienced Swift developer; faster with AI-assisted implementation, but real-device testing time doesn't compress. Deferred until after v1: audio mixer, Lumetri-style color and LUTs, Basic 3D (Z position and 3D rotation), bezier keyframe curves, nested sequences, multicam, dockable workspaces, OTIO/XML interchange, and plugins.

## Risks and mitigations
- **Composition track limits.** AVFoundation has a practical cap on how many video layers it can decode at once. Mitigation: reuse composition tracks by packing non-overlapping clips onto the same track (A/B-roll allocation), and warn beyond about 8 simultaneous layers.
- **VFR iPhone footage.** Conform it to the sequence rate in the compositor by picking the nearest source frame, and mark it in the Project panel.
- **HDR metadata correctness.** Check every export by probing it again (see Verification). Keep HLG as the default HDR output because it degrades gracefully on SDR displays.
- **Timeline UI performance.** Build it in AppKit/Core Animation from the start, not SwiftUI.

## Easy build & run (a requirement, set up in M0 and kept green by CI)
The target is **clone → open → ⌘R**, needing only Xcode, with no Homebrew, no Apple Developer account and no extra setup steps.
- **Commit the generated `Splicewright.xcodeproj`.** XcodeGen stays a maintainer-only tool for editing `project.yml`. CI fails if the committed project doesn't match `project.yml`, so people who only build never need XcodeGen installed.
- **No third-party dependencies at build time.** Use only Apple frameworks and the local Swift package. SwiftLint runs only in CI, never as a required build phase.
- **Signing is set to "Sign to Run Locally"** (ad-hoc) in Debug, so it builds on any Mac without a team ID. Release signing is a separate config.
- **`Makefile` shortcuts** (thin wrappers around `xcodebuild`):
  - `make run` builds Debug and opens the app
  - `make test` runs all tests
  - `make release` builds a Release `.app`
  - `make dmg` packages it
  - `make doctor` checks the Xcode version and macOS version and prints clear errors
- **Test media isn't required to build.** Fixtures are small clips created by `scripts/make-fixtures.sh`, using ffmpeg if installed or AVFoundation-generated clips if not. Tests that need missing fixtures are skipped with a message instead of failing. No git-lfs.
- **Prebuilt downloads.** Pushing a `v*` tag makes CI build a `.dmg` and attach it to a GitHub Release, so you can install it without building. A notarized build needs a paid Apple Developer account (currently $99/yr; verify). Without one, the DMG is unsigned and macOS requires right-click → Open the first time. The README will explain both cases.
- **README "Quick start"** (written in M0 and kept up to date): requirements (macOS 15+, the Xcode version), the three steps to build, `make` targets, and troubleshooting (for example, selecting the right Xcode with `xcode-select`).

## Verification
- **Build-and-run check:** CI does a fresh clone and runs `make test`. Before each milestone is marked done, a manual fresh clone on the M4 must succeed with open → ⌘R.
- **Unit tests** (Swift Testing for SWCore; XCTest for SWMedia so tests can skip where a CI host lacks an encoder): every SWCore edit operation, including ripple/roll/slip/slide edge cases, linked clips, undo/redo round trips, and RationalTime math at 29.97 and 59.94.
- **Media probe tests:** a fixture matrix covering iPhone HLG/Dolby Vision 4K60 HEVC, H.264 4K30 SDR mp4, HDR10 PQ HEVC mov, a ProRes clip and a VFR clip. Each one must report the expected codec, fps, bit depth and transfer function.
- **Golden-frame render tests:** render chosen timestamps through the compositor offscreen and compare against reference images by PSNR threshold. Cover SDR, HLG, PQ, tone-mapped HDR→SDR, dissolve midpoint, and a title over video.
- **Export round-trip tests:** export short sequences with each preset, then re-probe with AVURLAsset to confirm the container, codec, profile (Main10), resolution, frame rate, duration (frame-exact), color primaries/transfer/matrix and audio. Optionally cross-check with `ffprobe` or `mediainfo` in CI.
- **Manual checks on the M4:** 4K60 HEVC HDR plays with 0 dropped frames at full resolution (overlay stats). Exported HDR files look correct in QuickTime Player and Photos. An HLG export plays properly on an iPhone. Proxy playback stays smooth and export ignores the proxies.
